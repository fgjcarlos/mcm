# Issue #305 — graphical configuration and recovery

Branch stack: `feat/305-01-recent-mfa-proof` → `feat/305-02-config-backend` → `feat/305-03-ui-workspace` → `feat/305-04-e2e-ci`; base: `origin/main` (`7e6d43d`). Delivery: stacked pull requests against `main`, one per slice (user selected a split instead of a single pull request). The original construction branch `feat/305-08-mfa-e2e-scripts` (`04cee50`) is the reference tree; the stack is rebuilt from its content because the original commits interleave across `internal/deploy/service.go`, `internal/server/app.go`, `internal/server/security.go` and `docs/openapi.yaml`, and a commit-boundary cut would produce broken intermediate states.

Verification: Go race suite, Go vet, gofmt, golangci-lint, frontend Vitest/build/lint, Redocly OpenAPI lint, docs lint, isolated live-Mosquitto E2E and the browser journey. Independent verification of the four declared risks is delegated to a verifier agent; a provider-quota failure is recorded as unverified, never substituted.

S7. "Exigir MFA configurado y una comprobación reciente antes de ejecutar estas operaciones sensibles." Applies to applying changes, recovering revisions and importing copies.

## Constraints on the cut

- **C1** — MFA enforcement on `POST /broker/config/apply` and `POST /deployments/apply` breaks the pre-rewrite UI and the `e2e-{deploy,prod,recovery,rollback,verify}.sh` scripts, which send no `X-MCM-MFA`. The enforcement therefore ships with the UI that can satisfy it, and with the scripts updated in the same change.
- **C2** — `golangci-lint` enables `unused`. `requireRecentMFA` is unexported, so it may only land in the pull request that first uses it.
- **C3** — The truthfulness fix (`pending_activation` instead of an unverified `active_verified`) changes what `scripts/e2e-broker-config.sh` observes, so the fix and the script update ship together.
- **C4** — The original commits interleave; the stack is rebuilt by content, not by cherry-picking whole commits.
- **C5** — `frontend/dist/index.html` is versioned and embedded (`//go:embed all:dist`). Every pull request that touches the frontend rebuilds it.

The cause was not the enforcement itself but the helper that satisfies it. `scripts/mfa-step-up.sh` enrolled TOTP on the **bootstrap administrator**, which changes how that account signs in, so every later login in the same job received an MFA challenge instead of a token and the following scripts failed. Two scripts that apply changes — `scripts/e2e-broker-settings.sh` and `scripts/tests/test-e2e-acl-scoped-listener.sh` — had never been updated to send the proof at all, and the reference tree had missed them too.
L8. The helper now creates a **dedicated operator**, signs in as that operator, enrolls TOTP for it and returns both the operator session and the proof, because the proof is bound to the session that requested it. The bootstrap administrator keeps its plain login. A fresh operator per call also means no two scripts share the consumed TOTP time steps of one account, which removes the same-window collision the high-water mark in `mfa_last_totp_step` would otherwise cause. The shell TOTP was verified against the Go implementation for six steps: all matched.
L9. The independent verifier was delegated over the final tree and returned a **FAIL** verdict with five findings: a blocking copy assertion this stack introduced, the API never returning `ErrBrokerRestartUnavailable`, no MQTT verification before the file was written despite the documentation promising a preflight, `capabilities.restart` being a type assertion that can report `true` for an adapter that cannot restart, and the early 404/400/422/503 returns of the recovery and copy handlers not being audited. The blocking assertion and the behaviour findings are corrected in the final pull request of this stack.
L10. The behavioural findings are corrected in PR 4. The adapter answers `CanRestart()` instead of being guessed with a type assertion: the file applier needs a reload command, the docker applier a container name. The root-configuration apply refuses a restart-required change the adapter cannot perform — `force` authorizes applying a change that needs a restart, it does not turn a reload into one — and runs the MQTT preflight before writing anything, so a configuration whose activation could never be observed never reaches the disk. `ErrBrokerRestartUnavailable` is no longer dead code.

The settings surface shares the root-configuration apply path and therefore shares its preflight.
